# 幺筒麻将实现与验收

规则版本：v1.0（2026-10-18）。实现基于本目录《幺筒麻将规则-v1.0.md》，不采用同目录其他草稿作为补充规则。

## 运行与范围

默认大厅选中幺筒麻将，支持一名玩家与三名本地 AI。通过 GamePort 接入原版 App / LobbyView / GameTableHud / MahjongTable3D / SettlementOverlay，复用原版主题、材质、牌面、头像、牌背、开局动画、碰杠胡演出、背景音乐与音效。原有玩法可在大厅切换，或用 `?game=legacy` 默认选择经典广麻。先前独立二维页面已经移除。

`npm run dev` 启动开发服务（默认 5173）；`npm run build` 输出 `dist/`。`npm run preview -- --port 4174` 可检查生产包。

上游真人联机依赖另一个未包含在本仓库的后端。此版本没有将幺筒请求发送给原版房间服务，也不提供未经适配的真人联机入口。若要联机，应在服务端运行同一套动作和结算规则，仅向各座位投影其可见状态。

## 交互

- 沿用原版操作：桌面单击出牌；触屏双击或向上滑动出牌。报听时先点“报听”，再打出带听牌提示的牌。
- 摸牌单独放在手牌右侧；自摸按钮由引擎核验并自动按合法方案亮牌。
- “听”标记提示哪些出牌能进入听牌。未见张数只扣除本人手牌和已公开牌，不读取 AI 暗手。
- 胡、碰在行为违规情况下仍保留，界面提示风险；实际选择后由引擎判包牌。
- 打开规则会暂停 AI，关闭后继续。托管复用原版操作栏。
- 胡牌先播放短演出，再显示结算。可查看牌桌、展开账单、导出 JSON、继续小局。
- 动效遵循 `prefers-reduced-motion`，原版声音设置分别控制音效和背景音乐。没有强制倒计时和自动代胡。
- 对局仅存于内存，刷新或离桌不保留。本地 AI 是轻量牌效策略，不宣称专业竞技强度。

节奏对齐后验收：幺筒专项61项；仓库全量2324项通过、2项上游既有跳过。类型检查与生产构建通过。新增假时钟边界测试覆盖真实音频等待、多响收齐响应、过渡期间重复操作、离桌/暂停取消，以及10个种子按真实时序完整托管到结算。原有20个种子的纯规则守恒测试继续保留。

浏览器验证原版大厅、3D牌桌、开局、单击出牌、主题切换、AI托管和结算。移动端沿用原版横屏入口。

## 与原版共享的节奏

这些时间直接来自原版共享配置或流程，不在幺筒分支复制另一套数值：

| 环节 | 复用来源 | 行为 |
| --- | --- | --- |
| 开场、掷骰 | `playOpeningCue` | 至少1250/1150ms，同时等待对应音频结束 |
| 发牌 | `dealInitialHands` | 四张一批260ms，最后单张150ms；幺筒关闭庄家跳牌，各13张后保留原报窗口 |
| 首摸、普通轮转 | `OPENING_PACE_MS`、`PACE_MS` | 原报确认完毕650ms后庄家首摸；无人响应450ms后下家摸牌 |
| AI | `AI_DELAYS` | 摸牌后650ms、普通响应500ms、杠后补摸550ms；AI碰后用原版650ms出牌节奏 |
| 碰杠衔接 | `PACE_MS` | 真人碰后350ms再开放出牌；明杠后550ms补牌；补杠先宣告，650ms后处理抢杠，成功后600ms补牌 |
| 报牌 | `playDiscardName` | 落牌音后80ms报牌，保存真实播放结束信号 |
| 胡牌 | `createSettlementTimeline` | 点炮先等待报牌结束，再等500ms；立绘1600ms＋退出400ms，3D演出2600ms，再亮牌1500ms；之后才显示积分变化、翻鸡与账单 |
| 特效音、减少动态效果 | 同一结算时序 | 3D特效开始320ms后播特效音；减少动态效果时沿用原版450/420/360ms阶段 |
| 动作字、飘分、公告 | `createLocalTransientEventPresenter` | 沿用原版2000/1050/1500ms生命周期 |

普通自摸展示阶段合计6100ms。点炮还须等待真实报牌音频和500ms过渡；原报与多响窗口属于幺筒规则差异，不能为了缩短时间跳过。纯规则引擎仍可同步运行，实时界面通过具名过渡边界推进；过渡期间不接受重复出牌或碰杠操作。

规则引擎的终局计算保持原子性；UI在共享亮牌阶段结束前显示旧积分，并保留尚未翻出的指示牌，避免提前透露结算。离桌或重开后，旧音频Promise及旧定时回调不能恢复旧对局。

`npm run test:yaotong`：文档金额算例、成牌与资格、操作判罚、热炮/抢杠/多响、末张、轮庄和确定性四 AI 完整对局。

完整对局测试使用20个固定种子，每一步断言实体牌总数108、每种四张、能够到达终局、净分之和为0。点炮多响后的共同胡牌张按文档分别归赢家，属于结算阶段的逻辑共用，不误判为物理牌墙新增。

具体算例包括：固定鸡杠翻鸡36、幺筒255鸡分、加礼与双骰每家710、普通碰65/45、预冲碰120/90、未听反赔、流局34、硬鸡胡10、包牌最低45、杀原报只加40、幺筒本牌点炮H+90与另两家30、癞子点炮责任不翻三倍、补杠被抢不收成功杠分、包三份见面礼。

Windows 沙箱若不允许系统临时目录中的文件重命名，可仅在测试进程内把 `TEMP` 与 `TMP` 指向仓库 `tmp/`，再执行 Vitest。该问题是测试运行环境限制，不需要关闭安全设置。


## 2026-10-19：WAV、座位反馈与逐条规则复核

本次以《幺筒麻将规则-v1.0.md》为唯一正式规则来源。用户明确确认：**预冲碰跨到普通阶段成功补杠，保留120鸡分，原责任家的30责任款另结**。不重复收取原碰的90鸡分；杠本身三家各20，见面礼另按最终四张归属处理。已同时补齐动作执行与逐家付款回归。

修复与呈现调整：

- 过手例外此前只比较H，同一清一色由普通炮35变成热炮/抢杠55可能被误放行。现同时记录此前放弃时的结构分，要求结构确实增长、H增长且H≥45；场景加分不能单独解除过手。实际摸牌才清除记录，碰牌不清除；被过手挡住的机会不触发必须胡义务。
- 一般包牌在原版适配结果中使用`draw`表示非胡牌终局，原标题因此误显示“荒庄”。幺筒现提供明确的包牌、荒庄、热炮胡、抢杠胡和多响标题。
- 报听/原报使用对应座位的常驻小标记和一次短脉冲；被杀报划去标记，亮牌时标烧鸡；胡牌开始先在原版动作字中显示选定主要牌型，各赢家座位分别标明。规则说明放在标题、辅助名称和账单，不在桌面重复铺文案。
- 幺筒出牌在出牌者旁短暂显示实际档位，使用“预冲30”等而非“+30”，避免误称即时所得。终局分数仍等原版演出完成才变化。
- 结算按任意两人抵消后的净额绘制方向箭头，切换玩家最多看三条。点击箭头展开该对玩家的双向分项；鸡分依据列出牌种、档位、数量及翻鸡倍率。净额与四人的最终积分变化一致，明细保留抵消前记录。
- 音频统一解析到用户更新的`public/audio/bgm/*.wav`和`sounds/*.wav`，包含原文件名`hu_effecct_sound.wav`。27张序数牌、碰杠胡、听、发牌、骰子、推倒、冲鸡、责任鸡、杠特效和两首BGM均有真实资源映射。旧调用名通过别名兼容，没有替代资源的旧点击、字牌、开场等声音直接跳过，不产生404或额外等待。发牌长音频不随每一批叠播；等待型音效保留实际ended/error及超时释放。
